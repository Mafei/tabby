# Tabby Linux UI/UX 设计方案 v1

推荐采用「轻量标签工作台」：低饱和蓝灰作为应用界面的底色，局部强调当前标签和输入窗格，保留终端自己的配色。默认保持顶置标签与一行工具栏，会话树按需展开。先评审整套视觉和交互，再分阶段修改产品。

**本包是原创设计提案，所有画面均为示意，不是实际 Tabby 截图。** 主机、目录、输出、时间、按钮状态都是虚构样例。SVG、PNG 和 PDF 不能证明产品已经实现这些布局或通过 GUI 测试。

## 设计依据与方向选择

以下结论属于本方案的设计判断，参考产品提供模式与取舍，并不意味着复制其界面，也不是用户研究结果。

| 公开资料 | 可借鉴的模式 | 本方案的取舍 |
| --- | --- | --- |
| [Ghostty 功能说明](https://ghostty.org/docs/features) | 平台自然的窗口界面，标签、分屏及主题能力 | Linux 窗口装饰尊重现有桌面环境；不照搬 macOS 标题栏 |
| [WezTerm 颜色与外观](https://wezterm.org/config/appearance.html) | 活动、非活动及悬停标签有独立状态；窗格变暗可配置 | 明确区分状态；本方案不用整块窗格透明度表达焦点，减少 RDP 下文字变淡 |
| [Windows Terminal 应用主题](https://learn.microsoft.com/en-us/windows/terminal/customize-settings/themes) | 应用界面颜色与终端配置有分工，窗口失焦也有状态 | 单独定义工具界面角色；不引入 Windows 的 Mica/Acrylic 效果 |
| [Windows Terminal 分屏](https://learn.microsoft.com/en-us/windows/terminal/panes) | 当前窗格与键盘切换有明确反馈 | 用窗格标题内短标记表达焦点，减少整圈边框 |
| [Konsole](https://apps.kde.org/konsole/) | 标签、配置、输出搜索及活动监测属于终端的核心导航 | 常用操作可达，较少使用的操作收进菜单 |
| [GNOME 键盘指南](https://developer.gnome.org/hig/guidelines/keyboard.html) | 操作具备键盘路径，焦点顺序可预期 | 保留终端的 Tab 输入语义，工具界面提供明确的焦点进入和返回路径 |

| 方向 | 适用情景 | 优点 | 成本或局限 |
| --- | --- | --- | --- |
| **A 轻量标签工作台，推荐默认** | 经常使用 2–8 个会话 | 延续 Tabby 标签和工具栏；终端面积充足；改动可分阶段 | 大量标签仍需要搜索、滚动和会话列表 |
| B 会话导航栏 | 10 个以上会话、多主机分组 | 会话身份与分组易扫描 | 固定占用横向空间；折叠层级增加导航成本，建议复用已有可选配置树 |
| C 极简全屏工作区 | 熟悉命令和快捷键的用户 | 终端面积最大 | 新用户难发现操作；连接异常和访问方式必须仍有可见出口，适合作为用户选项 |

推荐 A，并让 B、C 保持用户选项。当前源码已有可选 `profile-tree`、四种标签位置、扩展工具按钮和快捷键系统，可复用这些能力。[固定基线的主界面模板](https://github.com/Mafei/tabby/blob/d83bf1b4904e439533d074aa6f7d3b48ebde5776/tabby-core/src/components/appRoot.component.pug)、[默认配置](https://github.com/Mafei/tabby/blob/d83bf1b4904e439533d074aa6f7d3b48ebde5776/tabby-core/src/configDefaults.yaml)。

## 信息架构与操作

顶层依次是窗口装饰、标签与工具栏、窗格标题、终端内容、紧凑状态条。窗口装饰由现有 frame 设置和 Linux 桌面决定，示意图中的 30px 装饰高度不作为实现约束。

标签展示序号、类型图标和用户名称。活动标签显示关闭按钮；非活动标签在悬停、键盘焦点或上下文菜单中提供关闭操作，并保留关闭快捷键。标签重命名和完整身份放在提示及上下文菜单内，长名称中间或尾部省略，完整名称可通过键盘获得。关闭后焦点回到可预期的相邻标签；仅有一个标签时回到已有开始页。

右侧主要工具按「打开会话、搜索、分屏、更多」组织。扩展提供的按钮仍走现有 provider；可配置工具优先级，窗口窄时将次要操作移入可访问的更多菜单。图标有可读名称、悬停提示与实际快捷键提示，不靠猜图标。

「打开会话」复用现有配置选择器：搜索、最近使用、保存配置、添加 SSH 主机入口；避免新增第二套互相冲突的配置存储。默认快捷键参考现有 Linux 的 `Ctrl+Shift+E` 打开配置、`Ctrl+Shift+P` 命令、`Ctrl+Shift+S/D` 左右/上下分屏及 `Ctrl+Shift+F` 搜索。实际提示读取用户当前绑定，配置树和菜单也是完整入口。[Linux 默认键位](https://github.com/Mafei/tabby/blob/d83bf1b4904e439533d074aa6f7d3b48ebde5776/tabby-core/src/configDefaults.linux.yaml)、[终端快捷键](https://github.com/Mafei/tabby/blob/d83bf1b4904e439533d074aa6f7d3b48ebde5776/tabby-terminal/src/hotkeys.ts)。

窗格标题简写 host/account/session 与访问角色；完整 socket、server、session 身份放在详情中，避免持续占用正文空间。状态条只呈现当前窗格的连接与访问状态，以及必要的编码或快捷操作。窗格标题与状态条是待评审的新增布局，不能把它们描述成已经实现的能力。

分屏维持单条可见分隔线和较宽的拖动命中区；当前输入窗格由标题内短强调线表达，终端文字不随窗格失焦而变透明。复制 tmux 标签仍进入新选择流程，既有同身份去重规则保持。

所有 UI 角色使用实色。无全窗口透明度、渐变、模糊或依赖阴影的状态识别；圆角和弱背景只提供层次，状态同时有形状、字重、图标或文案。下列值同时保存在 `tokens.json`。

应用主题与终端主题分工：默认应用 UI 可跟随系统深浅色；用户选择应用主题可固定。现有 `followsColorScheme`、第三方主题和 custom CSS 的行为需要兼容方案，不能全局覆盖。若提供「UI 随终端方案」选项，应沿用已有安全派生颜色并检查文本及标记对比，不强行套固定调色；仅在默认 Linux 主题实现第一阶段。

## 尺寸、字型与密度

| 项目 | 推荐值，CSS px | 说明 |
| --- | --- | --- |
| 间距基准 | 4 | 大部分间距采用 4 的倍数 |
| 标签栏 / 标签 | 44 / 36 | 上下各 4px，默认工作密度 |
| 标签宽度 | 优选 220，最小 144 | 长名称省略；不足时滚动，保留选中项可见 |
| 标签间距 / 左右内距 / 圆角 | 4 / 12 / 6 | 不给每个标签增加边框 |
| 活动标记 / 键盘焦点环 | 2 / 2 | 与悬停、选中分开建模 |
| 工具命中区 / 紧凑选项 | 32 / 28 | 图标 16px；实际禁用项仍有可读提示 |
| 窗格标题 / 状态条 | 28 / 24 | 多窗格时允许隐藏状态条，但异常入口可达 |
| 终端内距 | 16 | 应提供密度选项并尊重用户既有设置 |
| 分屏可见线 / 拖动区 | 1 / 10 | 指针拖动与键盘调整均可达 |
| UI 正文 / 次级文字 | 13/20，12/18 | 字体使用平台可用 UI 字族，活动项字重 600 |
| 终端示例 | 16/24 | 仅画稿示例；不覆盖用户终端字体设置 |

不要把终端重绘或改变列宽作为换肤的副作用。新增标题/状态区域必然影响可用行数，应在进入或退出分屏、缩放窗口时正确通知终端尺寸。1px 线按实际缩放后的设备像素检查，不能假定 125% 或 150% DPI 仍锐利。工具按钮和标题文案需验证中文、拉丁字母、长账户名和长会话名。

顶部与底部标签的标记靠终端一侧；左/右标签改为 2px 竖标记。相同的 selected、hover、focus、blur 状态适用于四个位置。小窗口优先保留活动会话和异常操作，工具收进更多，标签滚动并提供会话列表；不将活动标签无限压缩，也不通过减淡文字腾出层次。可选导航栏默认关闭，建议宽度 240–320px 并允许拖动调整。

## 状态与异常流程

| 状态 | 视觉反馈 | 操作与语义 |
| --- | --- | --- |
| 活动标签 | 局部背景、2px 标记、600 字重 | 当前会话可辨；不要将其等同于键盘焦点 |
| 非活动标签 | 可读的 secondary 标签，无整圈边框 | 仍可点击、键盘切换；无需低透明度 |
| 悬停 | 弱底色与关闭操作 | 不显示活动标记，不暗示已经切换 |
| 键盘焦点 | 独立 2px 外环 | 焦点可在非活动标签；激活才切换会话 |
| 窗口失焦 | 保留活动形状与字重，标记改实色中性 | 不降低全窗口或终端文字透明度 |
| 有新输出 | 小圆点配可访问提示 | 不不断闪烁；允许关闭活动提示 |
| 只读 | 锁形图标和「只读」文字 | 本窗格禁止向远端发送输入；仍允许选择、复制和查看输出 |
| 正在重连 | 图标、下一次重试时间、「取消」 | 保留终端输出，不伪装成可输入；取消后可重新连接 |
| 占用导致暂停 | 局部提示条与「选择方式」 | 自动恢复暂停，不自动接管，不踢其他客户端 |
| 身份丢失或替换 | 错误图标、具体原因、「查看详情」 | 保留原输出，不隐式重建同名会话 |

「选择方式」明确列出 **共享**、**只读**、**接管**。共享允许多个客户端参与；只读对本客户端禁用输入；接管按钮明确说明会断开其他附着客户端，必须由用户主动选择，不能作为自动恢复路径。UI 不承诺硬 fencing。自动重连仅恢复原 host/account/socket/server/session 身份；缺失、同名替换或 server 重启对应清楚错误，不能悄悄创建新的 session。

提示条放在受影响窗格附近，不遮挡历史输出。认证 prompt、host key 确认、tmux 缺失、连接失败和 session 身份错误分开文案，并提供取消或返回选择；「缺少 tmux」可以选择普通 SSH，不默认安装。取消流程同时覆盖嵌入 prompt 与 modal，旧 generation 的成功/错误结果不恢复过期 UI。UI 文案只显示需要用户决定的信息，具体错误放在可访问详情内，不暴露密码或私钥内容。

普通 SSH 的连接恢复与 tmux 身份恢复用不同文案，避免让用户误以为普通远端进程也有持久恢复保证。断线倒计时不每秒抢占辅助技术读屏；宣告状态变更和重要失败，尊重系统减弱动画设置。

模态打开时焦点进入搜索或首个决策项；Esc 关闭、焦点返回触发控件。终端输入 Tab、Escape、Ctrl 字符的既有行为保持；只有焦点实际在 UI 控件中时才使用列表键盘导航。工具菜单、标签上下文菜单和长名称提示需要键盘完整路径。当前终端内容与连接状态分别使用合理的辅助技术语义，不能把所有输出和每次倒计时都当作警报。

## RGB565 与验收门槛

设计令牌已检查 2 套主题共 **30 组前景/背景配对**。每组同时检查原始 RGB888 和按 R5/G6/B5 截断再复制位数的 RGB565 值：普通 UI 文本至少 4.5:1，重要选中/焦点/分屏标记至少 3:1；比较使用原始浮点值，不先四舍五入。方法与原始比值在 `contrast-audit.json`，计算器在 `generate_design.py`。

门槛依据 [W3C 文本对比说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 与 [非文本对比说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。悬停弱底色和装饰分隔不作为唯一状态线索；重要标记与相邻区域有明确对比。细线抗锯齿可能降低实际可见性，因此令牌数学通过仍需要像素与远程桌面验证。

活动底色相对栏底色的 RGB565 对比约为深色 1.27:1、浅色 1.11:1，这是为了减少重边框感的主动取舍。新方案以形状、600 字重及对比至少 3:1 的局部标记识别选中项；**不能直接沿用旧实现要求活动面与栏面至少 1.7:1 的测试，再宣称本方案通过**。若后续实现本方案，应调整对应验收契约，并保留文本及标记的严格检查。

两张 `RGB565-simulation` 图片由本包原创 PNG 逐像素量化生成，不缩放、不裁剪。它们用于比较设计在降低色深后的变化，既不是 xrdp 实测，也不模拟全部编码、网络或抗锯齿行为。PNG 内部和 PDF 均保留「非产品截图」标记。

## 实施拆分与待评审点

设计评审后建议三个阶段：

1. 默认 Linux 主题的角色令牌、标签/悬停/键盘焦点/窗口失焦样式；保持布局和连接逻辑。完善四个标签位置、主题兼容与实际像素检查。
2. 工具栏归并、配置选择器排版、窄窗口与大量标签导航。复用已有配置与键位，不增加第二套会话模型。
3. 窗格标题、紧凑状态条和异常提示布局；绑定已有 SSH/tmux 状态，补完整应用交互与网络恢复回归。引入额外垂直区域前确认终端面积与 resize 行为。

建议用户先评审：是否接受低饱和蓝灰方向；选中项的小面积标记是否足够；是否希望默认显示窗格标题和状态条；默认工作密度是否合适。这是设计选择的评审，不是合并、发布或部署审批。本次交付完成后不自动修改产品代码。

Android 可以参考同一套「状态用图标与文字、主题与 ANSI 分工」原则，但本包的桌面尺寸与控件排列不适合作为手机/平板标准。本次未修改 Android 分支；Android 实现和兼容测试由原任务继续管理。
